## What is MCP?

The [Model Context Protocol (MCP)](https://modelcontextprotocol.io) is an open standard that allows AI assistants to interact with external tools and services. Kakiyo's MCP server enables you to control your LinkedIn automation using natural language through AI assistants like Claude, ChatGPT, Grok, Cursor, and other MCP-compatible clients.

## Authentication options

Kakiyo's MCP server supports two authentication paths:

<CardGroup cols={2}>
  <Card title="OAuth (recommended)" icon="shield-check">
    Default for Claude, ChatGPT, Grok, Cursor, Claude Code, and any other MCP client that supports remote HTTP. Users log in on Kakiyo, select a team, and approve the connector. No API key is pasted. Manage and revoke these connections from **Developer → MCP**.
  </Card>
  <Card title="API key header (optional)" icon="key">
    Fallback for clients that cannot run OAuth. Uses a 40-character team-scoped API key in the `Authorization` header.
  </Card>
</CardGroup>

## Quick Start

### 1. Open Developer → MCP

In the [Kakiyo Dashboard](https://app.kakiyo.com), go to **Developer → MCP**. Copy the MCP server URL (`https://api.kakiyo.com/mcp`). Most clients, including Claude, ChatGPT, Grok, Cursor, and Claude Code, connect over OAuth and do not need an API key.

### 2. Configure Your MCP Client

Choose your MCP client and add the configuration:

<Tabs>
  <Tab title="Claude.ai (Web & Desktop)">
    Use Custom Connectors in the Claude web or desktop interface. No API key is required — Kakiyo uses OAuth.

    1. In Kakiyo, open **Developer → MCP** and copy the server URL
    2. Go to [claude.ai](https://claude.ai) → **Customize** → **Connectors**
    3. Click **Add custom connector**
    4. Enter the URL: `https://api.kakiyo.com/mcp`
    5. Click **Add**, then **Connect**

    Claude will open a secure OAuth flow on `app.kakiyo.com`. You'll log in (if needed), choose the team Claude should access, and approve the connection.

    <Frame caption="Kakiyo OAuth consent screen for an MCP connector">
      <img
        src="https://public-kakiyo.b-cdn.net/Integrations/Screenshot%202026-04-23%20at%2010.27.31%E2%80%AFPM.png"
        alt="Kakiyo MCP connector consent screen"
      />
    </Frame>

    <Note>
      Custom Connectors require a Claude Pro, Max, Team, or Enterprise subscription.
    </Note>

    <Warning>
      Claude custom connectors do not support pasting a raw API key in the connector dialog. Use the OAuth flow above.
    </Warning>
  </Tab>
  <Tab title="ChatGPT">
    ChatGPT connects over OAuth (Client ID Metadata Documents, with Dynamic Client Registration as a fallback). No API key is pasted.

    1. In Kakiyo, open **Developer → MCP** and copy the server URL
    2. In ChatGPT, open **Settings → Connectors**
    3. Turn on **Developer mode**
    4. Add a remote MCP server and paste `https://api.kakiyo.com/mcp`

    ChatGPT will send you through the same Kakiyo consent screen to pick a team and approve access.

    <Note>
      Custom MCP connectors in ChatGPT require Developer mode. Without it, only directory connectors appear.
    </Note>
  </Tab>
  <Tab title="Grok">
    Grok connects over OAuth using Dynamic Client Registration. No API key is pasted.

    1. In Kakiyo, open **Developer → MCP** and copy the server URL
    2. Go to [grok.com/connectors](https://grok.com/connectors)
    3. Choose **New Connector → Custom**
    4. Paste `https://api.kakiyo.com/mcp`

    Grok will open Kakiyo's consent screen. Approve the selected team to finish.
  </Tab>
  <Tab title="Claude Code (CLI)">
    Add Kakiyo as a remote HTTP server. Do not pass an Authorization header — that skips OAuth.

    ```bash
    claude mcp add --scope user --transport http kakiyo https://api.kakiyo.com/mcp
    ```

    Then authenticate:

    1. In Claude Code, run `/mcp` and choose **Authenticate**
    2. Or run `claude mcp login kakiyo`
    3. Kakiyo opens the consent screen so you can pick a team

    <Note>
      If you already added Kakiyo with `--header "Authorization:Bearer …"`, remove that server and add it again without the header so OAuth can run.
    </Note>
  </Tab>
  <Tab title="Cursor">
    Cursor connects over the same OAuth flow. Add the URL only — no headers.

    1. Open **Settings → Tools & MCP**
    2. Add a remote MCP server with `https://api.kakiyo.com/mcp`
    3. Press **Connect** and approve the Kakiyo team on the consent screen

    Or add it in `.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "kakiyo": {
          "url": "https://api.kakiyo.com/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab title="OpenCode">
    If your OpenCode version supports MCP OAuth, add the URL without headers and complete the Kakiyo consent screen. Otherwise use an API key:

    ```json
    {
      "mcp": {
        "kakiyo": {
          "type": "remote",
          "url": "https://api.kakiyo.com/mcp",
          "headers": {
            "Authorization": "Bearer YOUR_API_KEY"
          },
          "enabled": true
        }
      }
    }
    ```

    After saving, restart OpenCode to load the MCP server.
  </Tab>
  <Tab title="Other Clients">
    Paste `https://api.kakiyo.com/mcp` as a remote Streamable HTTP server. The client should start OAuth when you connect.

    | Setting | Value |
    |---------|-------|
    | **URL** | `https://api.kakiyo.com/mcp` |
    | **Transport** | Streamable HTTP |
    | **Auth** | OAuth 2.1 (recommended). Optional: `Authorization: Bearer YOUR_API_KEY` if the client cannot run OAuth |
    | **Method** | POST |

    Refer to your client's documentation for the exact configuration format.
  </Tab>
</Tabs>

## Find leads from your AI assistant

Your AI assistant can search for new people to contact, show you who matches, and send the people you pick straight into a campaign, all from the chat. It uses the same Lead Finder as the dashboard, so every search started from your assistant also appears under **Searches** in Kakiyo.

<Info>
  Finding leads over MCP is available to workspaces on an **active trial or paid plan**. Other workspaces get a message with a link to Billing.
</Info>

### How it works

<Steps>
  <Step title="Describe who you want">
    Ask in plain language, for example *"Find CTOs at fintech startups in London with 20 to 200 employees"*. Your assistant turns this into one precise search and saves it in Kakiyo.
  </Step>
  <Step title="Get matches from Kakiyo's database">
    Within a few seconds you see a ranked list: name, title, company, location, a match strength (**strong** or **possible**) and a short reason why each person fits. Contact details such as email or phone are never shown here.
  </Step>
  <Step title="More results from LinkedIn and the web (automatic)">
    If the database has fewer than 10 strong matches, Kakiyo also searches LinkedIn and the web in the background. This usually takes one to two minutes, and your assistant brings the extra people in as they are verified.
  </Step>
  <Step title="Pick and send">
    Tell your assistant who to keep, or say *"add the top 30"*, and which campaign to use. The assistant confirms with you first, because the campaign's LinkedIn profile will start contacting these people.
  </Step>
  <Step title="Follow the import">
    Your assistant reports how many people were added and how many were skipped, for example people the campaign already contacts or people on your Do Not Contact list.
  </Step>
</Steps>

### Tips for better results

- **Be specific.** Name the role, seniority, industry, location and company size or stage. *"VPs of Sales at B2B SaaS companies in the Nordics with 50 to 500 employees"* works far better than *"sales SaaS Nordics"*.
- **Mention your campaign.** People that campaign's LinkedIn profile is already talking to are left out automatically.
- **Refine instead of starting over.** *"Only companies above 100 people"* updates the same search and doesn't use up a new one.
- **Ask for more.** *"Show me the next ones"* pages through the same search for free.
- **Continue in the dashboard.** Every search started in chat is under **Searches** in Kakiyo, where you can review it or send more people later.

### Daily limits

To keep searching fast and fair for everyone, lead searches over MCP have daily limits per workspace. The limits use a **rolling 24-hour window**: each search frees up again exactly 24 hours after you made it.

| What | Limit per 24 hours |
|------|--------------------|
| New searches | 20 |
| Refining an existing search (changing its description) | 20 |
| Searches that also look on LinkedIn and the web | 10 |

These never count toward a limit:

- Asking for the same search again, or for the next page of results
- Checking on a search's progress
- Adding people to a campaign
- Searches you run in the Kakiyo dashboard

When a limit is reached, your assistant tells you when the next search frees up. If the LinkedIn and web limit is reached, you still get the matches from Kakiyo's database. You can keep working in the dashboard at any time.

### Lead Finder tools (3 tools)

| Tool | Description |
|------|-------------|
| `find_leads` | Search for people from a plain-language description, refine a search, or get the next page. Returns ranked matches, starts the LinkedIn and web search when needed, and shows how many searches you have left today |
| `get_lead_search` | Read-only. Collects the extra LinkedIn and web results as they arrive, and follows the import after you send people to a campaign. Waits on the server for up to 25 seconds per call |
| `add_leads_to_campaign` | Sends the people you picked (or the top N matches) from a search into a campaign. People already contacted by that campaign and people on your Do Not Contact list are skipped. A search can be sent once; start a new search for different people |

<Note>
  Use `customData` for freeform outreach context unique to that lead — for example the intent signal, post they engaged with, or research note that explains why you are contacting them now. The agent injects it into openers, replies, and follow-ups whenever the prompt includes `{{customData}}`.

### Prompts (3 tools)

Read and patch AI message templates.

| Tool | Description |
|------|-------------|
| `list_prompts` | List prompt templates (id, name, type, model only — no section text) |
| `get_prompt` | Get one prompt as sections (`context`, `firstMessage`, `followUps` or `comment`) plus update guidelines. Call this before `update_prompt` |
| `update_prompt` | Patch those sections. Omitted fields stay stored. `followUps` replaces the whole array (max 3; `delay` is 1-30 days after the previous message). A 4th follow-up is rejected |

<Note>
  MCP agents should not send a raw prompt JSON blob. Patch `context`, `firstMessage`, or `followUps` separately. The API assembles and validates the stored JSON. To change one follow-up delay, copy the full `followUps` array from `get_prompt` first.
</Note>

## Manage access

OAuth connections are listed on **Developer → MCP** in the dashboard. Each row shows the client (Claude, ChatGPT, Grok, Cursor, or a generic MCP client), the granted scopes (`mcp:read`, `mcp:write`), and the team it can access.

Revoking a connection deletes that client's refresh tokens for the workspace. The client must approve Kakiyo again to reconnect. One-hour access tokens expire on their own.

API-key clients are managed from **Developer → API Keys**, not from the MCP connections list.

## Technical Details

### Endpoint

```
POST https://api.kakiyo.com/mcp
```

### Authentication

Kakiyo's MCP server accepts two authentication methods on the same `/mcp` endpoint:

<Tabs>
  <Tab title="OAuth 2.1 (recommended)">
    Custom connectors use the standard MCP OAuth flow. When a client calls `/mcp` without a valid token, Kakiyo responds with:

    ```
    HTTP/1.1 401 Unauthorized
    WWW-Authenticate: Bearer error="invalid_token",
                             resource_metadata="https://api.kakiyo.com/.well-known/oauth-protected-resource/mcp",
                             scope="mcp:read mcp:write"
    ```

    Kakiyo exposes the standard MCP/OAuth metadata endpoints:

    | Endpoint | Purpose |
    |----------|---------|
    | `GET /.well-known/oauth-protected-resource/mcp` | Protected resource metadata ([RFC 9728](https://datatracker.ietf.org/doc/html/rfc9728)) |
    | `GET /.well-known/oauth-authorization-server` | Authorization server metadata ([RFC 8414](https://datatracker.ietf.org/doc/html/rfc8414)) |
    | `GET /mcp/oauth/authorize` | Authorization endpoint (redirects to the Kakiyo consent screen) |
    | `POST /mcp/oauth/token` | Token endpoint (authorization_code + refresh_token grants) |

    Kakiyo's OAuth implementation supports:

    - OAuth 2.1 Authorization Code grant with **PKCE (S256)**
    - **Client ID Metadata Documents** (CIMD) — no manual client registration required
    - Resource Indicators ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707.html)) targeting `https://api.kakiyo.com/mcp`
    - Refresh tokens with rotation
    - Team-scoped access tokens (approval binds the connector to one Kakiyo team)
  </Tab>
  <Tab title="API key (Bearer header)">
    Legacy and programmatic clients can authenticate with a 40-character team-scoped API key:

    ```
    Authorization: Bearer {your_40_char_api_key}
    ```

    API keys remain available for clients that cannot run OAuth. If a client supports both, prefer OAuth and omit the Authorization header.
  </Tab>
</Tabs>

### Transport

The MCP server uses **Streamable HTTP** transport, which is stateless and compatible with most MCP clients.

### Rate Limits

MCP requests follow the same rate limits as the REST API:
- Rate limits are per-team, not per-key
- Lead Finder tools also have [daily limits](#daily-limits) per workspace (rolling 24 hours)

### Error Handling

Tool errors are returned in MCP format:

```json
{
  "content": [{
    "type": "text",
    "text": "{\"error\": \"campaign_not_found\", \"message\": \"Campaign does not exist\"}"
  }],
  "isError": true
}
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="How do I disconnect an MCP client?">
    Open **Developer → MCP** in the Kakiyo dashboard and revoke the connected session. Clients using an API key are disconnected by deleting that key under **Developer → API Keys**.
  </Accordion>
  <Accordion title="Claude says 'Couldn't reach the MCP server'">
    - Confirm `https://api.kakiyo.com/mcp` is reachable and returns `401` with a `WWW-Authenticate` header
    - Remove the existing custom connector in Claude and re-add it using the same URL
    - Make sure you're not trying to paste a raw API key in the Claude custom connector dialog — use the OAuth flow for `claude.ai`/Claude Desktop
  </Accordion>

  <Accordion title="Claude OAuth flow opens but approval fails">
    - Sign in to `app.kakiyo.com` first, then retry the Claude connector flow
    - Make sure your user account has access to at least one Kakiyo team
    - Approval binds the connector to the team selected on the consent screen; switching teams later requires reconnecting
  </Accordion>

  <Accordion title="Connection refused or timeout">
    - Check that you're using `https://api.kakiyo.com/mcp` with Streamable HTTP
    - For OAuth clients (Cursor, Claude Code, Claude, ChatGPT, Grok), add the URL without an Authorization header and complete the Kakiyo consent screen
    - If you chose the API-key path, verify the key is 40 characters and prefixed with `Bearer `
  </Accordion>

  <Accordion title="Authentication failed">
    - For OAuth: revoke and reconnect from **Developer → MCP**, and confirm you approved the correct team
    - For API keys: the key is team-specific, 40 characters, and must be prefixed with `Bearer `
    - Generate a new key from the dashboard if you are on the header path and issues persist
  </Accordion>

  <Accordion title="Lead search says subscription required">
    - Finding leads over MCP needs an active trial or paid plan. Start a trial or reactivate your subscription from **Billing** in the dashboard, then ask again.
  </Accordion>

  <Accordion title="Lead search says the daily limit was reached">
    - Your workspace used its MCP searches for the last 24 hours. The message says when the next one frees up.
    - You can still refine or page through searches you already made, follow imports, and use the Lead Finder in the dashboard without limits.
  </Accordion>

  <Accordion title="My assistant can't add leads to a campaign">
    - Make sure the campaign has a LinkedIn profile assigned and that the profile isn't restricted.
    - A search can be sent to a campaign once. Ask your assistant to start a new search for different people.
    - If you changed the search after seeing the results, ask your assistant to show the results again and pick from the new list.
  </Accordion>

  <Accordion title="Tool not found">
    - The MCP server has 52 tools — some operations (like agent creation) require the dashboard
    - Use `verify_api_key` to confirm your connection is working
  </Accordion>

  <Accordion title="Agency tools not working">
    - Workspace tools require an Agency plan
    - Verify your team is on the correct plan in the dashboard
  </Accordion>
</AccordionGroup>
